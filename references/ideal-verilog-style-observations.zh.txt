# Ideal/bad Verilog corpus observations

The quality gate is shaped by the migrated `ideal-verilog-code` and `bad-verilog-code` corpora under `tests/cases` as well as the detailed project rule files.

Observed high-signal traits in the ideal corpus:

- Ports consistently use direction prefixes: `i_` for inputs, `o_` for outputs, and `io_` for bidirectional ports.
- Module parameters use `C_` uppercase naming; state parameters use `ST_` uppercase naming.
- Internal registered outputs use `_o` suffixes and are connected to top-level `o_` ports through explicit `assign` bridges.
- The preferred indentation unit is Tab; ideal files are overwhelmingly Tab-indented.
- Mature modules use dense nearby comments for parameters, ports, declarations, assigns, FSM branches, generate branches, and instances.
- Complex modules are organized by Chinese region banners such as 配置参数区域、状态参数区域、输出信号连线、状态机区域、主要任务处理区域、模块实例化区域.
- FSMs use explicit state parameters and separate state/register, next-state, and task/output logic blocks.

Observed high-signal traits in the bad corpus:

- Many files are minimal legacy snippets without bilingual headers, region banners, or semantic comments.
- Legacy port names often lack `i_`/`o_`/`io_` prefixes.
- One `always` block often drives multiple targets, which makes automated refactoring and comment insertion risky.
- Inline `wire x = ...` declarations, missing default branches, block comments, and simulator-only constructs appear in stress cases.
- Bad/reference fixtures are useful for non-strict analysis, but not as generation targets.

The machine-readable metrics are stored in `assets/ideal_bad_style_metrics.json`. The deterministic implementation is in `runtime/verilog_generator/quality_gate.py`, and structural extraction is delegated to `runtime/verilog_generator/formatter_ast.py` rather than a new parser.


Additional hardening from the corpus review:

- Generated deliverables must not keep template or placeholder comments such as `端口信号注释` or `参数解释说明中文`; the strict gate treats them as semantic-comment failures.
- New generator output should include the complete bilingual Erie header instead of relying on later manual formatter cleanup.
- Non-trivial port lists should include Chinese group banners (`全局信号`, `用户接口`, or protocol interface groups) in the module header.

The corpus metric extraction is reproducible with `scripts/analyze_verilog_style_corpus.py`; the delivery-time constraints remain implemented in `runtime/verilog_generator/quality_gate.py` and backed by `runtime/verilog_generator/formatter_ast.py`.

The stable regression corpus is maintained in `tests/cases`, with migrated RTL under `tests/cases/ideal/rtl` and `tests/cases/bad/rtl`, and behavioral expectations in `tests/cases/manifests/verilog_case_manifest.json`. Use manifest expectations to distinguish strict-fail bad fixtures, compatibility `*_good.v` samples, stress-pass compatibility fixtures, and legacy reference modules; generated strict-pass deliverables remain covered by the runtime mock/gate regression.
